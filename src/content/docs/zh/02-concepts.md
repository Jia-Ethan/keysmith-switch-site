## 提示词库

每个 Agent 有自己的一组提示词。一条提示词就是一段 Markdown 正文，加上标题、标签和编辑历史。库保存在本机的 `~/.keysmith-switch/`，不会上传到任何地方。

库里的提示词分两组显示：**当前部署**（正在这个 Agent 里生效的那一条）和 **提示词库**（其余的）。

## 部署

部署就是把库里的一条提示词交给 Agent 使用。每个 Agent 同一时间只有一条由 Switch 部署的提示词，部署新的一条会替换旧的。

部署永远分两步：先 **预览**（只计算、不写入），确认后才 **执行**。停用也是一样。

## 适配器

Switch 自己不直接改写 Agent 的配置文件，而是交给每个 Agent 的开源适配器去写：

| Agent | 适配器 | 版本 |
| --- | --- | --- |
| Claude Code | claude-keysmith | 7.2 |
| Codex | codex-keysmith | 0.6.0 |
| Grok Build | grok-keysmith | 0.7.0 |
| ZCode | zcode-keysmith | 0.3.2 |

适配器的版本和 App 锁定在一起：版本对不上时，确认部署会被拒绝，而不是冒险写入。适配器负责目标格式、备份、漂移检测和恢复；Switch 负责提示词库、版本、哈希校验、计划预览和操作记录。

## 漂移

部署之后，如果有人（或别的工具）手动改过 Agent 的配置，Switch 会发现配置和部署时不一致，这叫 **漂移**。漂移时提示词通常仍然生效，但为了不覆盖你的修改，部署会被拦下，页面会告诉你下一步点哪里。详见[部署计划](/docs/deploy/)。

## 版本

「清理」之前，Switch 会先把当时的状态存成一个 **版本**：部署中的提示词正文、记忆文件的原样字节等。设置里的「版本」页可以回滚或删除它们。注意区分：

- **编辑历史**：一条提示词自己的修改记录，在提示词详情里看。
- **版本**：清理前对整个 Agent 状态的快照，在「设置 → 版本」里看。
