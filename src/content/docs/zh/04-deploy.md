## 计划里有什么

点「部署」或「生成部署预览」之后，Switch 会把提示词正文交给适配器，请它**只计算、不写入**，然后把结果整理成一个对话框：

- **现在 → 部署后**：左边是这个 Agent 现在用的提示词，右边是部署后会用的那一条。
- **一句话说明**：会替换现在的提示词，还是第一次部署；原来的内容会先自动备份；部署后要重启 Agent 才生效。
- **详细信息**（默认收起）：会写入哪些文件、备份放在哪里、配置的指纹（部署前后的哈希）、适配器给出的警告。

你点 **部署** 之后，Switch 才会让适配器真正执行。执行时用的是刚才预览过的那一份计划；如果预览之后提示词被改过，执行会被拒绝，你需要重新生成预览。

## 停用

顶部的 **停用** 会生成一份停用计划：移除 Switch 部署的提示词，把配置还原到部署前的样子。你自己写在配置里的其他内容不受影响。

## 被拦下的时候

适配器发现不安全时，会拒绝写入，并告诉你原因。常见的几种：

| 提示 | 意思 | 怎么办 |
| --- | --- | --- |
| 配置文件在上次部署之后被改过 | 有人（或别的工具）手动改过这个 Agent 的配置，也就是「漂移」 | 按提示点「整理配置」或「清理」 |
| Keysmith 管理的那几行被挪动或改写过 | 只是托管的几行位置变了 | 点 **整理配置**：先备份配置文件，再把这几行放回原位，你自己的设置原样保留 |
| 找不到有效的部署记录 | 部署记录被清理或损坏了 | 用「清理」清掉过期的记录 |
| 部署前的配置备份已经不在了 | 停用时没法按原样还原 | 点 **保留当前配置并停用**：只移除 Keysmith 写入的那一段 |
| 权限不足 | Windows 上当前用户对 Agent 目录没有完全控制权限 | 授予完全控制权限后重试 |

被拦下时**不会改动任何文件**。弹窗会直接写出适配器给的原因，并告诉你下一步点哪里。

## 部署之后

- **重启 Agent。** Claude Code、Codex、Grok Build 要开一个新会话，ZCode 要重新打开 App，新的提示词才会被读到。
- **部署记录。** 每次部署、停用都会留下操作记录，备份放在 `~/.keysmith-switch/backups/<操作 id>/`。
- **相同正文不重复。** 部署的正文和库里已有的一条完全相同时，Switch 直接复用那一条，不会悄悄改它的标题或标签。
